# Cloudflare 전환 분석 및 개발 계획

작성일: 2026-10-29. 개발 브랜치: `cloudflare-test`.
분석 시작 시 HEAD와 main: `e095b102c2d98c05d73cfbcfc41901ca2a9806b7`.

## 기존 구조

- 서비스 파일: index.html(2,106줄), config.js, .nojekyll.
- index.html: 기존 CSS/HTML, C(업무 규칙), S(상태 분리), R(과목 목록), P(인쇄 SVG), H(분반배정 JSON), Reset, 화면/키보드/행 정렬, 조회/저장.
- config.js의 외부 웹앱 주소와 iframe/postMessage RPC가 서버 의존성의 경계다.
- 서버 소스는 저장소에 없다. 실제 운영 저장소/암호화/권한 구현은 추정하지 않는다.
- 공통 설정과 교과군 자료를 별도로 저장한다. globalRevision, 교과군 revision, operationId가 클라이언트 계약에 포함된다.
- schemaVersion=1 백업 형식과 slots, legacy, unmapped, importRef, 배열 순서를 보존해야 한다.

## 구현 순서

1. 기존 디자인과 UI 이벤트를 유지하고 순수 업무 규칙을 공유 모듈로 추출.
2. 브라우저 RPC를 동일 출처 fetch로 교체. 인증 화면과 두 단계 권한 유지.
3. Pages Functions API와 D1 JSON 문서 저장 구현. 서버 검증과 권한 비교 추가.
4. SQL 조건부 갱신, 전역 변경 트랜잭션 가드, 작업 ID로 충돌/재시도 보호.
5. 가상 데이터, 실제 로컬 D1 런타임 통합 테스트, 브라우저 회귀 테스트 추가.
6. 클라이언트/API/DB 시간 측정, 반복 벤치마크, 시험 배포 절차 문서화.

## 경계

- main 브랜치, 원격 저장소, 기존 운영 서버와 운영 데이터는 변경하지 않는다.
- 개발/시험은 가상 데이터와 로컬 또는 별도 시험 D1에서만 수행한다.
- 운영 데이터를 자동으로 가져오는 기능과 자동 원격 배포는 추가하지 않는다.
- UI 전체 재작성과 관계형 전체 정규화는 이번 전환에 포함하지 않는다.
- 무료 운영을 위해 폴링 없이 교과군 단위 조회/명시적 저장, 인덱스, 제한된 작업 기록을 사용한다.
- 실제 무료 티어 CPU/요청 한도와 네트워크 지연은 로컬 측정과 별도로 시험 배포 후 확인한다.
