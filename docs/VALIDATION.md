# 검증 및 측정

## 실행한 검증

시험 환경: Windows, Node.js 24.22.1, Miniflare 4.20260730.0/workerd,
Wrangler 4.154.0, Playwright 1.64.1, 설치된 Edge의 headless 모드.
compatibility_date는 로컬 시험과 Pages 모두 2026-07-30으로 고정했습니다.
실제 개인정보와 운영 서버 연결 없이 가상 자료만 사용했습니다.

### 자동 테스트: 25개

- 원본 CSS 해시 일치, 외부 RPC 코드 제거 확인.
- JSON 상태 왕복과 ID/출처 보존, 시수 합계, 초과 배정·교과군 참조 거부.
- 하위 분반과 합산 배정 보존·분배, 제출/잠금, 초기화, CSV 수식 방지, 두 인쇄 SVG.
- 분반배정 JSON 검증 및 다른 교과군 보존.
- 실제 D1 런타임에서 같은 교과군 동시 저장 충돌, 교과군별 독립 저장.
- 같은 작업의 동시 재전송/재시도, 다른 내용으로 작업 ID 재사용 거부.
- 전역 트랜잭션 충돌·원자성·신규 교과군 생성, 고아 교과군 방지.
- 검증 후 바뀐 교과군 버전을 전역 SQL 가드에서 거부.
- 일반 사용자의 구조 변경·잠금 우회 거부, 관리자 재개방.
- 교과군 간 ID 중복을 SQL 제약으로 거부하고 기존 버전·자료 보존.
- 새 교과군의 통합 검증 실패가 전역 버전·기존 자료를 변경하지 않음.
- 입력 모드의 과목 원본 연결과 합산 배정 나누기 허용.
- 크기 초과 사전 거부, 로그인 제한, 외부 Origin 거부, 세션 폐기·비밀번호 변경.
- 서버 pepper와 access/admin 구분, 저장 검증값을 로그인 증명으로 재사용할 수 없음.
- 배포 Functions 번들에 PBKDF2 deriveBits가 포함되지 않음.

D1은 SQL 동작을 흉내 낸 객체가 아니라 Miniflare/workerd의 실제 SQLite 기반 바인딩을
사용합니다. 테스트 SQL 진입점은 tests/worker.mjs에만 있고 배포 Functions에 포함되지 않습니다.

### 브라우저 시험: 10개 시나리오

접속과 배당표 표시, 편집/저장과 충돌 시 입력 보존, 교과군 전환/새로고침,
서버 저장 후 응답만 잃어버린 상황의 동일 작업 ID 재시도, 관리자·제출·확정·재개방,
분반배정 JSON 가져오기, 백업·CSV 다운로드, JSON 복원, 두 인쇄 SVG,
교과군 생성·학교 설정·성능 측정을 자동 실행합니다.

실제 OS 인쇄 대화상자 대신 window.print 호출과 인쇄용 SVG 생성을 검증합니다.
외부 폰트 요청은 브라우저 테스트에서 차단하므로 PNG는 시스템 대체 글꼴일 수 있습니다.
전체 UI CSS의 원본 일치는 별도로 검사합니다. 실제 종이 출력·운영 브라우저별 출력 검수는 별도입니다.

### Pages CLI 검증: 3단계

Wrangler의 Pages Functions 빌드, 별도 로컬 DB의 migration 적용,
동일 DB의 가상 SQL 자료 적재를 확인했습니다. 원격 Cloudflare 리소스는 사용하지 않았습니다.

GitHub Actions는 main push와 PR에서 동일한 로컬 시험을 실행합니다.
Actions는 배포·Cloudflare Secret을 요구하지 않으며 운영 D1을 사용하지 않습니다.

## 성능 측정

pnpm benchmark는 매번 별도의 가상 DB를 생성합니다.
가상 규모: 교과군 12개, 교사 144명, 과목 96개, 실제 분반 및 배정 각 576개.
로그인 후 교과군 조회와 저장을 각각 30회 실행하고 p50/p95/최댓값과 D1 읽기·쓰기 행 수를 남깁니다.
로그인 시간에는 브라우저를 모방한 로컬 암호 계산이 포함되고 서버 시간은 Server-Timing으로 구분합니다.

원시 결과는 test-results/benchmark.json, 브라우저 결과는 test-results/browser.json,
화면 PNG와 인쇄 SVG도 test-results/에 생성합니다. TEST_RESULTS.md에는 마지막 로컬 측정 요약을 기록합니다.
CI의 하드웨어와 병렬 작업 부하에 따라 수치는 달라집니다. 고정된 ms 기준으로 CI를 실패시키지는 않습니다.

앱에서도 관리자 → 학교 설정 → 성능 측정 또는 브라우저 콘솔의
window.ALLOCATION_PERFORMANCE.snapshot()으로 최근 100개 측정값을 볼 수 있습니다.
입력 내용·비밀번호·토큰을 측정값에 저장하지 않으며 외부 수집 서버를 사용하지 않습니다.

## 확인 범위의 한계

위 로컬 시험 자체는 원격 D1 지연·무료 CPU 제한 집행을 포함하지 않습니다.
2026-10-30에 별도 원격 시험을 추가했으며, 실제 수치와 한계는
[원격 배포 보고서](CLOUDFLARE_DEPLOYMENT_2026-10-30.md)에 기록했습니다.
해당 시험 프로젝트·DB와 일회성 원격 시험 스크립트는 main 전환 때 삭제했습니다.
상시 회귀 검증은 위 로컬 자동 테스트로 유지합니다.
로컬 API 시간과 원격 네트워크 시간은 wall time이며 Cloudflare CPU time과 다릅니다.
기존 운영 데이터와 그 서버 내부 소스는 시험하거나 이전하지 않았습니다.
