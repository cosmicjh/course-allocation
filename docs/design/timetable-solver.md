# 시간표 작성·검증: 확정 배당 → 솔버 JSON → Windows 로컬 계산

Status: 1차 설계 승인 (2026-11-13). 후속: 설치 없는 브라우저 계산은 `docs/design/timetable-browser-solver.md`(2026-11-14 승인). 원본: 인계서 `timetable-integration-handoff.md`(2026-11-10), `시간표검증기_통합.html`, `시간표_정확솔버_Colab.ipynb`, 교과배당표 XLSX(SHA-256은 인계서 §8). 원본 파일과 실데이터는 저장소에 넣지 않는다.

## Context

시간표는 지금 세 단계로 따로 만든다. 교과배당표 XLSX를 `시간표검증기_통합.html`에 올려 모델 JSON을 만들고, 그 JSON을 Colab 노트북(OR-Tools CP-SAT)에 올려 계산한다.
확정 배당은 이미 이 저장소(`shared/domain.js` 상태, D1 `sheets`)에 있다. 그래서 XLSX를 거치지 않고 이 데이터에서 바로 모델을 만든다. 계산은 학교 Windows PC에서 바로가기로 연다.

**1차 완료 기준**: 통합 시스템에서 확정 배당 선택 → 솔버 JSON 내보내기 → 바로가기로 로컬 화면 열기 → JSON 선택·계산 → 결과 확인·엑셀 다운로드.
통합 사이트가 로컬 프로그램을 직접 호출하는 연결과 통합시간표 등록은 2차 이후로 둔다.

**사용자 결정 (2026-11-13)**
- 위치는 이 저장소다. 기존 사전 설계(`docs/design/curriculum.md`)의 "병합 위치 = timetable-cloudflare"는 1차 범위에서 변경한다. 결과 등록은 후속 단계로 남긴다.
- 런타임은 휴대용 `setup.cmd`로 준비한다. 공식 Python embeddable과 해시가 고정된 휠을 앱 폴더에 설치한다. 관리자 권한이 필요 없고, 실행 정책의 영향을 받지 않는 `.cmd`를 쓴다.
- 실데이터는 첨부 XLSX로 검증한다. XLSX로 만든 로컬 상태를 쓰고 운영 DB에는 접근하지 않는다. 실데이터와 산출물은 Git 밖에 둔다.
- 솔버 옵션은 로컬 화면에서 실행마다 정한다. D1 스키마는 바꾸지 않는다.

## 데이터 흐름

```
course-allocation (브라우저)                          학교 PC (127.0.0.1)
state(잠긴 교과군) ─ exportSolverModel ─> model.json ─> 로컬 화면 ─ POST /api/runs
                                                         │            └─ 별도 프로세스: validate → build → solve(3단계) → extract
                                                         │                 → 독립 검사기 → result.json, result.xlsx (runs/<id>/)
                                                         └─ GET /api/runs[/id] : 새로 열어도 상태·결과 확인
```

## 1. 모델 내보내기 (Node, 이 앱)

- 새 모듈 `shared/timetable-model.js`에 순수 함수 `exportSolverModel(state, {exportedAt})`를 둔다. 반환값은 `{model, errors, warnings}`다.
  - `coursesOf`, `groupsOf`, `normalizeName`, `sum` 등 `shared/domain.js`의 함수를 재사용한다.
- **매핑**
  - `group.kind==='homeroom'`(라벨 `학년-반`)은 `bans[{grade, cls, subject, teacher, hours, art}]`로 내보낸다.
  - `kind==='moving'`은 `blocks[{grade, block: group.label, blockLen, div: slot.label, subject, teacher, hours}]`로 내보낸다.
  - 배당 1건(`assignments` 행)이 모델 1행이다. 여러 교사가 나눈 배당과 `3C1` 같은 세부 분반을 그대로 보존한다.
  - `blockLen`은 같은 기본 블록에 속한 슬롯 시수의 최댓값이다(HTML과 같은 규칙).
  - 과목명은 저장된 이름 그대로 쓴다. `통합사회`와 `통합사회2`는 합치지 않는다. 확인된 과목 ID가 같을 때만 같은 과목으로 본다.
- **역할 기본값**
  - 부장: `teacher.isLead`
  - 강사: 이름에 `강사`가 포함된 교사(로컬 화면에서 수정 가능)
  - 미술 `art`: 교과군 이름이 `미술`인 경우
- **v1 호환 + 추적 필드**
  - 각 행에 `rowId`, `teacherId`, `courseId`, `sectionId`를 추가한다.
  - 최상위에 `source: {term, departmentRevisions, exportedAt}`와 `classes: {grade: classCount}`를 추가한다.
  - Colab은 알 수 없는 키를 무시하므로 기존 노트북에도 그대로 올릴 수 있어야 한다.
  - `options`에는 노트북 기본값을 넣는다(weights 1, `pairAllowList` [], `gangsaDayCount` {}, 인계서의 기본 종속 관계).
- **내보내기 차단 오류**
  - 시수가 있는데 확정되지 않은 교과군
  - `legacy`(합산 배정 미분리) 또는 `unmapped` 잔존
  - 이름이 같은 교사
  - 시수가 정수가 아니거나 0 이하인 행
  - 블록 안 교사 배당 합 > `blockLen`
  - 학급별 주간 합 ≠ 31(반수업 + 해당 학년 블록 길이)
  - 각 오류는 교과군·과목·분반 이름으로 위치를 알려 준다.
- **UI (2026-11-14 변경)**: 내보내기 진입점은 통합시간표(`timetable-cloudflare`, 저장소 `cosmicjh/curriculum`) 관리자 화면의 **시간표** 탭이다. 탭 위치는 "시수배당표"와 "이동수업 배치표" 사이이고, 관리자만 볼 수 있다. 탭에는 확정 배당 점검 결과, "솔버 모델 내보내기" 버튼, 학교 PC 로컬 솔버 설치·실행 안내를 둔다. 통합시간표는 `exportSolverModel`을 vendor 사본으로 공유한다. 시수배당 앱에 임시로 두었던 버튼은 제거한다.
  - 현재 열린 학기를 내보낸다. 이미 있는 학기 전환 경로가 있으면 재사용한다.

## 2. Windows 로컬 솔버 (새 폴더 `timetable-solver/`)

- **배포·실행**
  - `setup.cmd`가 Python embeddable(버전·SHA-256 고정)과 `requirements.txt`의 `ortools`·`openpyxl`을 `runtime/`에 설치한다.
    - 휠은 `--require-hashes`로 받고, Python zip은 `certutil`로 해시를 검증한다.
  - `setup.cmd`는 바탕화면에 `start.cmd` 바로가기를 만든다.
  - `start.cmd`는 `127.0.0.1:8765`에 서버를 띄우고 브라우저를 연다. 이미 떠 있으면 브라우저만 연다.
  - 서비스·작업 스케줄러·시작 프로그램에는 등록하지 않는다. 콘솔 창을 닫으면 종료된다.
- **서버**: 표준 라이브러리 `ThreadingHTTPServer`로 정적 화면과 JSON API를 같은 주소에서 제공한다.
  - `127.0.0.1`에만 바인딩한다. Host 헤더를 검사하고, Origin이 다른 POST는 거부한다. 1차에는 CORS를 열지 않는다.
  - 계산은 한 번에 하나만 실행하고, 진행 중인 계산은 취소할 수 있다.
- **실행 저장**: `runs/<id>/` 폴더(Git 제외)에 `model.json`, `options.json`, `status.json`(원자적 쓰기), `log.txt`, `result.json`, `result.xlsx`를 둔다.
  - 서버를 다시 시작했을 때 실행 중으로 남아 있지만 PID가 죽은 실행은 "중단됨"으로 표시한다.
- **엔진 `tt_solver/`**: 노트북 셀 9·10의 `build`, `teacher_occupancy`, `discomfort_terms`, `_step_cost`, `extract`를 전역 변수 없이 거의 그대로 옮긴다.
  - 탐색 순서와 파라미터를 유지한다.
    - 1단계: 반수업 배치 최대화, 1800초, 16워커, `num_violation_ls=1`
    - 2단계: 최고 불편 최소화, 600초, 8워커, 1단계 힌트 사용
    - 2.5단계: 같은 형평에서 총 불편 최소화, 120초, 1단계 힌트 사용
  - **시작점 탐색(2026-11-13 사용자 승인, 노트북 탐색 순서와의 의도적 차이)**
    - 실데이터 진단에서 2학기 모델이 기본 1단계 1,800초 안에 UNKNOWN이었다. 같은 배당의 유효해는 존재했고, "일반교사 하루 최소 2시간" 규칙만 끄면 약 85초에 해를 찾았다.
    - 0단계로, 이 규칙만 뺀 완화 모델을 먼저 푼다. 그 해를 1단계 원래 모델의 힌트로 쓴다. 완화 해는 결과로 채택하거나 출력하지 않는다.
    - **기본값은 0초(생략)다(2026-11-14 결정).** 실데이터 진단에서 0단계 모델은 seed에 따라 73~168초에 해를 찾거나 300초 안에 찾지 못했다. 찾은 완화 해를 힌트로 넣어도 1단계는 1,800초 안에 풀리지 않았다. 0단계는 화면·CLI에서 선택할 때만 쓴다.
    - 로컬 화면에서 이전 실행 결과를 시작점으로 고를 수 있다. 결과 행은 `rowId`로 대응한다. 시작점을 고르면 0단계는 생략한다. 실데이터에서 유효한 이전 결과를 시작점으로 쓰면 1단계가 7.4초에 OPTIMAL이었고, 형평 단계까지 독립 검사기를 통과했다. 권장 사용법이다.
    - 학교 규칙과 독립 검사기는 그대로다.
  - 단계마다 상태, 목적값, 소요 시간, 채택 여부를 기록한다.
  - **유효 해 보존**: 2·2.5단계가 실패하면 직전 단계의 해를 채택한다.
  - **종료 상태 구분**: 사전 검증 오류 / `MODEL_INVALID` / `INFEASIBLE`(불가능 증명) / `UNKNOWN`(제한 시간 내 판정 못 함) / 성공(채택 단계)
  - **의도적 차이(테스트 포함)**
    - 불편 점수 변수의 하한·상한은 가중치와 시수로 계산한다. 현재의 -50 하한 버그를 고치는 것이며, 기본 가중치에서는 결과가 같다.
    - 이동수업 배치표 격자는 블록 슬롯 배치로 만든다. 모든 슬롯에 수업이 있는 정상 입력에서는 결과가 같다.
  - 결과 행에는 `rowId`를 붙인다.
- **독립 검사기 `checker.py`**: 엔진 코드를 import하지 않고 모델과 결과 행만으로 판정한다.
  - 교사 중복(실제 시간 슬롯 기준)
  - 학급별 31칸이 정확히 1개씩 채워졌는지
  - 배당행별 배치 시수 = 입력 시수
  - 블록 슬롯 규칙: 슬롯이 서로 다른 요일, 같은 학년 블록 간 겹침 없음, 같은 슬롯에 `(div, 과목)` 중복 없음
  - 부장 금1, 3학년 진로 금1, 일반교사 1·7교시 일수와 요일별 시수 범위, 최대 3연강, 점심, 미술 2+1, 종속 과목, 강사 출근일수, 하루 2회 분리
  - 불편 점수를 다시 계산해 엔진 값과 비교한다.
  - 검사를 통과하지 못한 결과는 "검증 실패"로 표시하고 엑셀에도 명시한다.
- **엑셀**: 노트북 셀 12의 4개 시트(교사별 시간표 · 이동수업 배치표 · 이동수업 분반 상세 · 검증 요약)를 같은 형식으로 만든다. 검증 요약에는 단계 상태와 검사기 결과를 추가한다.
- **화면** (`web/`, 모노톤·Pretendard·반응형)
  - 입력: 모델 JSON 선택, 이전 HTML의 설정 JSON(`고교학점제_설정`) 선택적 불러오기(`pairAllow` → `pairAllowList` 변환)
  - 옵션: 부장·강사 목록, 가중치, 하루 2회 허용 과목, 강사 출근일수, 종속 과목, 블록 금지 칸, 단계별 제한 시간
  - **적용 여부 표**
    - 실제 적용되는 고정 규칙
    - 원본 HTML에는 있지만 솔버에 연결되지 않은 설정(`artBlock`, `noLunchBlock`, `spread`, `coverage`, `coverageSubjects`, `bujaFridayP1Forbidden`): "미적용"으로 표시
    - 강사 출근일수는 상한, 하루 2회는 "교시 차이 3 이상"이라고 명시한다.
  - 실행 목록·진행 상태, 결과 요약(교사별 표), 엑셀 다운로드
