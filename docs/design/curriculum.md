# 시간표 생성 모듈 병합 설계 (통합시간표)

Status: 사전 설계 승인 (2026-11-12). 상세 설계는 미완료.

> **2026-11-13 변경**: 1차 시간표 계산은 `docs/design/timetable-solver.md`를 따른다. 확정 배당 내보내기와
> Windows 로컬 솔버는 이 저장소(시수배당)에 두고, 솔버는 브라우저가 아닌 학교 PC의 로컬 Python 프로세스에서 실행한다.
> 아래의 통합시간표(`timetable-cloudflare`) 결과 등록·검사기 공유·미리보기 경로는 후속 단계 설계로 유지한다.

이 문서는 사용자가 2026-11-12에 승인한 사전 분석과 방향만 담는다. 시간표 생성 코드(설정용 html,
설정 json, ipynb)는 아직 검토하지 않았으므로, 솔버 방식과 json 필드 수준의 계약은 정해지지 않았다.
"미확정 사항"이 해소되기 전에는 구현을 시작하지 않는다.

## 목표와 범위

### 목표

- 따로 동작하는 시간표 생성 코드를 통합시간표에 병합한다. 현재 흐름은 설정용 html에서 설정 json을 만들고,
  코랩에 올린 ipynb가 그 json대로 실행하는 방식이다.
- 통합시간표에 이미 모이는 자료(시수배당, 분반배정, 이동수업 배치표)를 생성기의 입력으로 쓰고,
  생성 결과를 통합시간표의 시간표 자료로 등록할 수 있게 한다.

### 범위

- 병합 위치는 통합시간표(`timetable-cloudflare`, Worker `school-timetable`, 저장소 `cosmicjh/curriculum`)다.
- 솔버 실행은 브라우저를 통한 로컬 실행을 우선 검토한다.

### 범위 밖

- Cloudflare Worker에서 솔버를 직접 실행하는 것.
- 결보강(`class-swap`)과 스터디룸 기능의 변경.
- 시수배당 루트 앱의 UI 재작성.

## 현재 제약과 관련 모듈

- 이 저장소 어디에도 수업을 요일·교시에 자동 배치하는 코드는 없다. 통합시간표는 학교가 만든
  전체교사시간표 엑셀을 가져와 표시·수정한다(`timetable-cloudflare/src/core.js`의 `parseTeacherMatrix`, `runtime`).
- 기존 등록 경로: `assets/import.js`가 `{format:'timetable-import', teacherRows, sections, students}`를 만들고,
  `src/domain.js`의 `prepareImport`가 미리보기를 검증하며, `commitImport`가 등록 전 백업 후 한 batch로 쓴다.
  모든 쓰기는 `expectedTerm`과 `expectedRevision` 가드를 거친다.
- 요일은 월–금, 교시는 최대 7로 고정되어 있다(`core.js:4-5`, `domain.js:9,22`).
- 분반배정 엔진(`assets/section-assignment/engine.js`)은 브라우저에서 도는 JS 지역 탐색이다.
  선택과목 분반을 시간블록 묶음에 넣고 학생을 배정하지만, 블록의 요일·교시는 정하지 않는다.
- 이동수업 배치표(`src/allocations.js`, 테이블 `room_allocations`)가 블록별 요일·교시·교실을 가진다.
- 시수배당에서 넘어오는 자료는 `C.timetableTransfer`(`shared/domain.js:338-352`)다.
  잠긴 교과군의 이동수업만 포함하고 학급 단위 수업은 빠지며, 교사를 ID가 아닌 이름으로 식별한다.
- `timetable-cloudflare`는 루트 저장소가 추적하지 않는 별도 저장소다. `AGENTS.md`와 `CLAUDE.md`가 없다.
- 시수배당 코드는 `timetable-cloudflare/vendor/course-allocation/`에 버전 기록 없이 수동 복사되어 있고,
  `hours-import.js`, `transport.js`, `server/api.js`, `index.html`이 루트와 다르다.
- 통합시간표는 `COURSE_DB` 바인딩으로 시수배당 D1을 직접 읽고 쓴다.
- 운영 원칙: Cloudflare 무료 요금제, 자동 훅·예약 작업 추가 금지, 운영 데이터와 실제 학생 정보 접근 금지.
- `AGENTS.md`는 시간표 솔버 동작과 데이터베이스 마이그레이션 변경을 고위험으로 분류하고 독립 검토를 요구한다.

## 승인된 아키텍처

역할을 다음과 같이 나눈다.

| 구성 요소 | 역할 |
| --- | --- |
| 통합시간표 Worker + D1 | 저장, 권한, 결과 검증, 등록. 솔버를 실행하지 않는다. |
| 솔버 | 문제 json을 받아 결과 json을 낸다. 서버 밖에서 실행한다. |
| 검사기 | 결과가 필수 제약을 지키는지 결정적으로 판정한다. 브라우저와 서버가 같은 모듈을 쓴다. |

진행은 두 단계다.

1. **솔버와 무관한 입출력 계약을 먼저 고정한다.** 통합시간표가 문제 json을 내보내고, 결과 json을 받아
   검사기로 다시 검증한 뒤 기존 미리보기·백업·등록 경로로 넣는다. 이 단계에서는 지금의 코랩 ipynb를
   솔버로 계속 쓴다.
2. **같은 계약 위에 브라우저 솔버를 얹는다.** 관리자 화면의 Web Worker에서 실행하고, 서버에는 결과만 보낸다.
   구현 방식(JS 이식, Pyodide, WASM 솔버)은 ipynb를 검토한 뒤 정한다. 다시 작성하는 비용이 크면
   1단계 상태로 코랩 실행을 유지한다.

## 데이터 구조와 흐름

```
시수배당(잠긴 교과군) ─ timetableTransfer ─┐
분반배정 엔진(블록 묶음, 학생 배정) ───────┼─> 문제 json ─> 솔버 ─> 결과 json
이동수업 배치표(블록 요일·교시·교실) ──────┘                         │
                                                                     v
                       검사기(브라우저) ─> 미리보기 ─> 검사기(서버) ─> 백업 ─> 등록
```

- **문제 json**: 교사, 분반, 주당 시수, 시간블록, 교실, 제약(필수와 선호)을 담는다.
- **결과 json**: 수업별 요일·교시 배치를 담는다.
- 필드 수준의 형식은 기존 설정 json과 ipynb 출력을 확인한 뒤 정한다.
- 서버는 결과 json을 신뢰하지 않는다. 브라우저에서 검증을 통과했더라도 서버가 다시 검사한다.
- 등록은 기존 `commitImport`와 같은 백업·revision 가드를 거친다.

## 기술 선택의 근거

- **서버는 검증만 맡는다.** 무료 요금제 Worker의 CPU 시간으로는 시간표 탐색을 돌릴 수 없고 Python 솔버도 실행할 수 없다.
- **계약을 솔버보다 먼저 고정한다.** 솔버를 바꾸더라도 서버와 화면이 영향을 받지 않고, 코랩판과 브라우저판을
  같은 입력으로 비교할 수 있다. 1단계만으로도 쓸 수 있어 위험이 가장 작다.
- **검사기를 공유한다.** 시수배당이 `shared/domain.js`를 화면과 서버에서 함께 쓰는 방식과 같다.
  화면과 서버의 판정이 어긋나지 않는다.
- **기존 등록 경로를 재사용한다.** 미리보기, 등록 전 백업, 원자적 batch, 동시 변경 가드를 새로 만들지 않는다.
- **브라우저 실행을 목표로 한다.** 교사 자료가 외부 연산 서버로 나가지 않고 비용이 들지 않는다.
  분반배정 엔진이 같은 방식으로 이미 동작한다.

## 기각한 대안

| 대안 | 기각 이유 |
| --- | --- |
| Worker에서 직접 풀이 | 무료 요금제 CPU 한도를 넘고 Python 솔버를 실행할 수 없다. |
| 유료 외부 연산 서버 | 무료 운영 원칙에 어긋나고 교사 자료를 외부로 보내야 한다. |
| 시수배당 루트 앱에 병합 | 교사시간표, 블록, 교실 자료가 통합시간표 D1에 있다. 사용자가 통합시간표 쪽을 선택했다. |
| 계약 없이 ipynb를 바로 브라우저로 이식 | 솔버 라이브러리가 브라우저에서 동작하는지 확인되지 않았고, 결과 품질을 비교할 기준이 없다. |

## 기존 기능과의 호환성 위험

- **기존 시간표 덮어쓰기.** 생성 결과가 `teacherRows`와 `lessons`를 바꾸면 수동 연결(`overrides`), 시간블록,
  결보강 계획과 예약, 이동수업 배치표가 가리키던 수업과 어긋날 수 있다.
- **재등록과 스터디룸 출석.** 명렬 재등록이 행을 지우고 다시 넣는 방식이어서 연쇄 삭제가 출석 기록에
  영향을 준 사례가 `studyroom_codex_handoff/docs/TIMETABLE_INTEGRATION_STUDY.md`에 기록되어 있다.
  생성 결과 등록이 학생·배정 테이블을 건드리지 않아야 한다.
- **`timetableTransfer` 확장.** 학급 단위 수업까지 생성하려면 전달 형식을 넓혀야 한다. 루트 앱, vendor 사본,
  `tests/domain.test.mjs`, 통합시간표의 가져오기 시험이 모두 영향을 받는다.
- **vendor 사본 불일치.** 루트와 사본이 이미 다르므로 한쪽만 고치면 차이가 더 벌어진다.
- **교사 이름 식별.** 동명이인이나 표기 차이가 있으면 시수배당의 교사와 시간표의 교사가 잘못 연결된다.
- **요일·교시 고정값.** 생성기의 설정이 월–금, 7교시를 벗어나면 기존 화면과 인쇄가 표시하지 못한다.
- **D1 마이그레이션.** 제약 설정이나 초안을 저장하게 되면 스키마가 바뀌고, 백업·복원 형식(v1)에도 반영해야 한다.
- **개인정보.** 문제 json과 결과 json에 교사 이름이 들어간다. 코랩을 쓰는 동안에는 이 파일이 외부 서비스에 올라간다.
  시험과 문서에는 가상 자료만 쓴다.

## 검증 가능한 합격 조건

상세 설계에서 구체화할 뼈대다.

1. 가상 자료로 만든 문제 json에 대해, 검사기가 결과의 필수 제약 충족 여부를 판정한다.
   필수 제약은 교사·학급·교실의 중복 없음, 분반별 주당 시수 일치, 같은 블록 수업의 동시 배치다.
2. 필수 제약을 어긴 결과 json을 보내면 서버가 등록을 거부하고 D1의 시간표 자료가 바뀌지 않는다.
3. 같은 결과 json에 대해 브라우저 검사기와 서버 검사기의 판정이 일치한다.
4. 등록은 등록 전 백업을 만들고, `expectedRevision`이 맞지 않으면 전체가 롤백된다.
5. 생성 결과 등록 뒤에도 학생, 수강 배정, 스터디룸 출석 자료가 등록 전과 같다.
6. 통합시간표의 `pnpm test:all`과 루트의 `pnpm test`가 통과한다.
7. Worker 번들에 솔버 코드가 포함되지 않음을 자동 시험으로 확인한다.
8. 브라우저 솔버를 도입하면, 같은 입력에 대해 코랩판과 제약 충족 여부·품질 지표를 비교한 결과를 기록한다.

## 미확정 사항

구현 전에 사용자 결정이나 확인이 필요하다.

- **생성 코드 검토.** 설정용 html, 설정 json 예시, ipynb, 결과물 예시를 아직 받지 못했다.
  솔버 라이브러리, 제약 목록, 실행 시간, 문제 크기, 결과 형식을 확인해야 한다.
- **브라우저 솔버 방식.** JS 이식, Pyodide, WASM 솔버 가운데 무엇을 쓸지, 또는 코랩 실행을 유지할지.
- **생성 범위.** 전체 교사 시간표인지 이동수업 블록만인지, 학급 단위 수업을 포함하는지.
- **등록 방식.** 생성 결과가 기존 시간표를 덮어쓰는지, 초안으로 따로 보관해 비교한 뒤 확정하는지.
- **제약 설정 저장.** 교사별 불가 시간 같은 설정을 D1에 저장할지, 파일로만 주고받을지.
- **교사 식별.** 이름을 유지할지 ID로 바꿀지.
- **저장소 경계.** 이 문서를 `cosmicjh/curriculum` 저장소에도 둘지, 루트의 역할 규칙을 그쪽에 적용할지,
  vendor 사본의 동기화 방식을 이번에 정리할지.
